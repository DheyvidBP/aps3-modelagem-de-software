# ADR 0001 - Fila com prioridade no RabbitMQ para as ordens

**Status:** Aprovado

## Contexto

Depois que uma ordem é validada ela precisa esperar até virar uma missão. Só que nem toda ordem tem a mesma urgência: se uma linha de produção está parada esperando material, essa entrega tem que sair antes de uma transferência comum de estoque.

A primeira ideia foi deixar as ordens no banco e ficar consultando de tempos em tempos com `ORDER BY prioridade`. Isso funciona, mas fica consultando o banco o tempo todo mesmo quando não tem ordem nova.

Também olhamos o Kafka, mas ele não tem prioridade de mensagem.

## Decisão

Usar uma **fila com prioridade do RabbitMQ** (`x-max-priority = 10`). Quando a ordem é aprovada, a API calcula uma prioridade de 0 a 9 (urgência + prazo) e publica a ordem na fila. O despacho sempre pega a ordem de maior prioridade.

O despacho só confirma a mensagem (ack manual) depois de criar a missão. Se cair no meio, a ordem volta para a fila.

Para nenhuma ordem ficar esquecida, se ela passar do tempo limite (SLA) a prioridade dela sobe 1.

## Consequências

- **Vantagens:** o despacho sempre recebe a ordem mais urgente, não precisa ficar consultando o banco e as ordens não se perdem se o serviço cair. O RabbitMQ já é usado no projeto para os alertas.
- **Desvantagens:** a prioridade tem só 10 níveis. Quando a prioridade de uma ordem sobe, ela é publicada de novo e a mensagem antiga continua na fila, então o despacho precisa ignorar mensagens repetidas.
